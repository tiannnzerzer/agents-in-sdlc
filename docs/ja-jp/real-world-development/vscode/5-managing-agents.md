GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行を自律的に行います。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。エディターを離れずに各差分を確認し、個々の変更を承認または取り消し、追加のプロンプトで作業を調整または拡張できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して承認します。
- セッションの途中でエージェントに依頼し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じるユーザー向けにライト モードも追加したいという要望がありました。新しい会話を始める代わりに、現在のセッションで作業を拡張するようエージェントに依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、作業の各段階が表示されます。各ファイルの差分はチャット内に表示され、**Keep** と **Undo** を選べます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案したら、チャット内の差分を確認します。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開き、このセッション中にエージェントが変更したファイル全体を確認します。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に変更の概要が表示されます。

## エージェントにライト モードを追加するよう依頼する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えも追加します。会話を続けると、エージェントは変更したコンポーネント、スタイルの方針、設定を local storage に保持する方法など、前の作業のコンテキストを引き継ぎます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を調べ、ライト モードの追加を提案する様子を確認します。
3. ハイ コントラストと同様に、追加された各編集をレビューし、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合は、チャット入力欄の隣にある **Stop** ボタンで停止し、追加のメッセージで意図を説明します。

> [!TIP]
> 進行中のセッションに追加指示を出すと、最初からやり直すより早く調整できます。たとえば「CSS を簡潔にして重複するセレクターの代わりに CSS 変数を使う」、「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを組み込む」、「両方の切り替えにキーボード ショートカットも追加する」と依頼できます。

## 作業内容をレビューする

コミットする前に、エージェントが変更したファイルをまとめて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルをすべて確認します。Astro コンポーネント、スタイル、関連テストが更新されている場合があります。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントのアクセシビリティ パターンが反映されていることを確認します。Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、local storage による設定の保持などが対象です。
4. 問題がなければ **Source Control** パネルで変更をステージしてコミットします。次のレッスンで公開します。

この演習では、次のことを行いました。

- アクセシビリティ エージェントの作業をリアルタイムで監視しました。
- 提案されたファイル編集を確認して承認しました。
